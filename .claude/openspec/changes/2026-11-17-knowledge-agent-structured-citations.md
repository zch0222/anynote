# 契约变更提案：知识检索 Agent 结构化引用与终态回答（Agent 版本 2）

关联：[运行契约](2026-11-15-ai-agent-runs.md)、[知识检索方案 §8、§9](../../../docs/ai-refactor/KNOWLEDGE_RETRIEVAL_PLAN.md#8-证据与引用)、[M16.8 记录](../../../docs/ai-refactor/AI_MILESTONES.md#真实模型首个问题清单类回答被改写成未找到2026-11-17-修复)。

## 背景

本机第一次用真实模型运行时，「我有哪些知识库」被回答成「未找到相关内容。已查询范围：默认范围」。
Trace 显示模型已正确调用 `kb_list` 并作答，但 `kb_list`、`kb_outline`、`kb_related` 的结果不登记证据，
验证器把零证据的 `ANSWERED` 改写为未找到；`kb_query` 的行虽登记为证据，模型给出的片段与证据文本对不上，逐字核对不过。

## 已确认范围

2026-11-16 用户确认按四项修复：清单类结果登记为证据、结构化行不要求逐字原文、回答放进 `agent_finish`、重写指令并升版本。
第三项在真实模型重放后调整为「`answer` 优先、同一条回复正文兜底」，原因与数据见 M16.8 记录（2026-11-17，待用户复核）。

- **`agent_finish` 参数**：`outcome`；`answer?`（不超过 8000 字，`ANSWERED` 时有内容则作为回答，否则取同一条回复的正文）；
  `citations[]`（`index` 从 1 起，`quote` 可为空）；`clarification_question?`。仍禁止多余字段。
- **结构化证据**：`kb_list`、`kb_query`、`kb_outline`、`kb_related` 返回的每一行登记为证据，工具结果里带 `evidenceId`；
  证据内部标记 `structured`（不进入事件），定位符带 `row: true`。不在本次显式范围内的行照常返回，但不登记、不带 `evidenceId`。
  结构化行已在工具结果里，不再重复进入证据层。
- **验证规则**：正文类证据仍要求 `quote` 逐字出现在证据文本里；结构化行只核对编号存在，不采用模型给的片段。
  证据为空时 `ANSWERED` 仍改写为固定未找到文案。
- **`citation` 事件**：字段集合不变。结构化行的 `snippet` 是服务端摘要，可为空（知识库为各类内容数量，如「笔记 3 · 资料 1 · 慕课 0 · 任务 2」）；
  `sourceType` 可能为 `kb`、`transcript`、`summary`；`locator` 可能带 `row`，前端按未知键忽略。
- **循环**：终态参数不合法、同轮多次调用终态时提示重交一次；终态与其他工具同轮时先执行其他工具，再请模型重交；
  缺少终态时重交的那一轮只提供 `agent_finish`；仍不合规按 `VALIDATION_FAILED` 结束（与此前相同）。
- **版本**：`run.started.agentVersion` 为 `"2"`。
- **不变**：Java 转发与落库、前端、OpenAPI baseline、用户可见文案均不改。
