## 这是什么

AI 相关模块（`services/ai`、`ai-service/` 以及连带的 Feign 契约与公共模块）的重构方案。四条核心判断：

1. **这是重建，不是优化。** 现有的聊天、PDF 问答、文档索引、语音转写流几条链路，静态阅读就能看出各自至少有一处断点
   （[调研报告 §2.3](./AI_RESEARCH.md#23-已核对的缺陷)），其中「取不到登录用户」已经在 M7.6 被真实浏览器验证。
2. **三段分工。** `services/ai` 做业务接入（认证、会话落库、配额、把事件流转给浏览器）；
   `ai-service` 是 Harness（任务循环、上下文、工具、模型接入、检索与索引）；
   `services/note` 是内容与权限的唯一权威来源。Python 不直接读业务库，也不自己判定权限。
3. **去掉 WebFlux 的收益首先是能正确工作。** `services/ai` 现在按 Reactor 写、却跑在 Servlet 栈上，
   登录用户、权限切面、内部签名因此都不生效。改回顺序写法后它们自然生效，长连接的并发由虚拟线程保证。
4. **检索不止一种。** 七种互补的检索方式以七个只读工具交给 Agent：全文、语义、条目级与大纲下钻、目录导航与范围读取、
   文内精确匹配、关系遍历、结构化查询。向量检索只是其中之一，并且可以整体关闭。

## 调研结论摘要

| 结论 | 对方案的影响 |
|---|---|
| `services/ai` 同时引了 WebFlux 与带 Servlet 的公共模块，实际跑在 Servlet 栈上；往 Reactor 上下文写登录用户的过滤器只有网关依赖 | 去 WebFlux 不只是性能话题，是修复 M7.6 第 1 条的途径 |
| WebFlux 经 `anynote-api-ai` 传递到了 note、file、job、manage | 迁移范围是「AI 链路上所有带 WebFlux 的模块」，不只是 `services/ai` |
| 三个 Feign 客户端指向不存在的服务名，文档索引端点不存在；不在请求线程上发出的 Feign 调用不带内部签名 | 随迁移一并修复，先写复现用例 |
| 现在的 PDF 问答每次提问都重新下载、解析、向量化整份 PDF，向量库在进程内存里 | 索引必须持久化、增量更新，并与在线问答分进程 |
| Python 服务没有鉴权、没有测试、没有容器化，解释器版本也没有固定 | 工程化补齐列为独立里程碑 |
| 仓库已有 Elasticsearch 8.7 与笔记索引，但笔记搜索只搜得到本人创建的，慕课索引没有数据来源 | 复用 Elasticsearch，新建索引；现有搜索端点一期不动 |
| 笔记、资料、慕课的权限判定各写了一遍，口径不一致；慕课的列表与详情用的是两套规则 | 在 note 里收拢成一处，检索与产品页面共用 |
| 笔记创建时权限写死为仅作者可见 | 普通成员在共享知识库里能检索到的主要是资料、慕课和自己的笔记。这是既有缺口，检索不绕开它 |

初版结论来自静态阅读；2026-11-14 已启动 dev 真实栈复核。逐项复现结果、被其他缺陷阻断的路径及容量数据见 [M16.0 验证记录](./AI_MILESTONES.md#m160-技术验证与拍板)。

## 范围

**做**：

- Harness 内核：任务循环与状态机、预算、上下文构建与清单、工具注册与行动面、事件协议、验证器、Trace、模型接入层
- Java：`services/ai` 及连带模块去掉 WebFlux，改用虚拟线程承载长连接；修复现有 AI 链路的缺陷
- 知识检索 Agent：全部知识库实体的语料与索引、七种检索方式、带定位的引用、「没找到就明说」
- note 服务：统一的权限判定、供检索使用的内部端点、变更记录
- Python 服务的内部鉴权、测试、容器化与 CI
- 新前端的事件协议接入、检索范围选择与引用展示

**不做**（理由见[总体方案 §1.2](./AI_REFACTOR_PLAN.md#12-非目标)、[知识检索方案 §1.2](./KNOWLEDGE_RETRIEVAL_PLAN.md#12-非目标)）：
联网搜索、会修改内容的 Agent 动作、长期记忆、多 Agent 协作、沙箱、独立的 AI 网关、知识图谱、扫描件文字识别、
网关与 notify 的迁移、Whisper 与翻译的功能重做、笔记权限模型的修改、旧前端的适配。
每一项在什么条件下需要补，写在[总体方案 §3.9](./AI_REFACTOR_PLAN.md#39-本期不建设的能力与触发条件)。

## 决策

2026-11-14 用户拍板：D1–D17 全部采用推荐项。D4 附加要求：**模型供应商必须能在运行时修改，不能全靠环境变量**，
落点见[总体方案 §5.5](./AI_REFACTOR_PLAN.md#55-模型接入层)「供应商配置」。

| # | 决策 | 结论（原推荐） | 备选 | 依据 |
|---|---|---|---|---|
| D1 | Harness 内核怎么实现 | **自建薄内核** | LangGraph；AgentScope 的 Python 版 | 循环、上下文、行动面是白皮书认为要自己掌握并做确定性测试的部分；框架里上下文怎么拼出来不透明，上下文清单难做（[总体方案 §5.4](./AI_REFACTOR_PLAN.md#54-harness-内核的实现方式决策-d1)） |
| D2 | 派生索引放哪 | **复用现有的 Elasticsearch**，新建索引 | 另加向量数据库；MySQL 全文索引 | 全文检索本来就要用它，8.7 已支持带过滤的向量近邻搜索；少一个中间件少一套权限过滤实现 |
| D3 | 嵌入与重排模型 | **经模型接入层调用，部署方式由部署方选；语义检索与重排是否默认开启，由评测的消融结果决定** | 固定用本地模型；固定用云端接口 | 白皮书 §15.8.2：向量与模型增强是可选能力，关闭时关键词检索也要能工作 |
| D4 | Python 的非敏感配置是否接 Nacos 配置中心 | **接**，支持热更新。**附加**：模型供应商运行时可改；凭据按 P1 存业务库密文，主密钥走环境变量 | 全部走环境变量 | 模型目录、预算、功能开关需要不重启调整；与 Java 服务的配置方式一致 |
| D5 | 用户身份怎么传给 Python 与 note | **透传网关注入的用户令牌** | 只传用户标识，靠内部签名信任 | 内部签名的密钥全栈共用且不绑定请求内容；透传令牌时 Python 最多只能以当前用户的身份读取 |
| D6 | 扫描版 PDF | **一期不做文字识别**，标记为无法提取文本 | 一期接入文字识别 | 先把有文本层的做好；识别质量与成本需要单独评估 |
| D7 | 内容变更怎么通知索引 | **变更记录表（与业务写入同事务）加游标拉取** | 消费 RocketMQ 消息；部署 Canal | 现有消息只覆盖笔记且发送失败会丢；游标天然支持重放；Python 不需要原生的消息客户端 |
| D8 | notify 服务是否一并去掉 WebFlux | **不在本期** | 一并迁移 | 不属于 AI 模块。它的写法与 `services/ai` 相同，按同样的推断也取不到登录用户（未验证），可以照本期的做法另开一批 |
| D9 | 服务改名 | **`anynote-ai-nio` 改为 `anynote-ai`**，破坏性切换，**不保留 `/api/aiNio/**` 别名**；前端和 CLI 同批改路由 | 保留旧名或旧别名 | 迁移后「nio」不再成立；三个 Feign 客户端本来就指向 `anynote-ai`；用户确认无生产环境，可破坏性升级 |
| D10 | 慕课在检索里的可见性 | **列表可见并且详情可读**（两套规则取交集） | 只按详情规则；只按列表规则 | 检索是发现渠道，不应该比列表多出一个入口；两套规则的不一致另行修复 |
| D11 | 知识库通知是否进语料 | **进，作为第三批** | 一期不进 | 通知有标题和正文，属于知识库内容；需要 notify 提供内部导出端点 |
| D12 | Whisper 的去向 | **留在 `ai-service/`，作为可选的独立进程与依赖组** | 拆成独立服务；并入索引 worker | 不拖累在线进程的镜像；功能本期不改 |
| D13 | Python 版本 | **固定 3.12** | 3.13；跟随本机默认 | 现有依赖钉的都是较早的版本，环境目前不可复现；具体版本在 M16.0 装齐依赖后确认 |
| D14 | 旧的 `POST /chat/completions` | **随新运行端点上线直接删除，不做旧格式兼容映射**；前端和 CLI 同批接入新事件流 | 保留一个版本 | 用户确认无生产环境，可破坏性升级，无需为线上旧客户端保留兼容期 |
| D15 | 知识库内容能发给哪些模型服务 | **由部署方在模型目录里显式标注**，默认只允许标注过的 | 不限制 | 提示词和嵌入接口都会看到知识库原文，属于数据出域 |
| D16 | 超管的默认检索范围 | **与普通用户相同**（自己加入的知识库）；显式指定知识库时才按超管权限 | 默认检索全部内容 | 否则超管的每次提问都会搜到所有人的私人笔记 |
| D17 | 现有的笔记搜索、慕课搜索 | **一期不动**，二期切到新索引 | 一期一并切换 | 控制一期范围；现有端点的缺陷已记录在调研报告里 |
