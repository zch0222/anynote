### 另外两处真实缺陷（本轮由真实浏览器实测暴露并修复）

首轮提交后继续逐条核对图例，发现两处**不是"画得不像"、而是"功能不对"**的问题：

| 问题 | 实测证据 | 修复 |
|------|---------|------|
| **库不存在时渲染一屏假数据** | `/notes/999999/overview` 后端返回 `{code:"A0301"}`（HTTP 200，靠 code 区分）→ 详情查询 `isError`，而其余五棵查询照样"成功"返回空列表。修复前页面照常渲染整页：头图写「未命名知识库」、5 格计数写 0、简介写「这个知识库还没有填写简介。」——**用户完全看不出这个库不存在**。同级 5 个 Tab 在同样输入下都不是这样 | 详情 `isError` 时最外层短路，渲染共用组件 `NotFoundState`（文案已在方案 12.0.3 定稿：找不到这个知识库 / 它可能已被删除，或者你还没有访问权限 / 回到知识库）。注意 `KnowledgeBaseMissing` 是**从未被任何地方引用的死代码**，本次改用统一的 `NotFoundState` 而不是复活它 |
| **概览路由继承了笔记 Tab 的加载骨架** | 图例 26 要求「加载骨架 · 封面 + 标题 + 两行文本 + 5 格计数，与真实版式同高」。而该路由段没有自己的 `loading.tsx`，按 Next 的就近规则继承了 `[baseId]/loading.tsx` 的**行列表**骨架——真实浏览器延迟 RSC 实测：过渡态 18 个灰块中**没有一个**落在头图或 5 格的位置上，数据到达时整页从"一列行"换成"卡片 + 网格" | 新增 `overview/loading.tsx` + 共用预设 `KnowledgeBaseOverviewSkeleton`，尺寸逐项对齐画板实测值（卡片 1000 宽 / 封面 96 / 5 格各 98 / 预览区同栅格断点）。修复后实测过渡态：`976x96@380,40`、标题、两行文本、`190x98@368,266`——与真实内容落点一致 |

这两条都按仓库规约**先写复现用例再改代码**：单测新增 3 条（第一条缺陷）+ 4 条（第二条缺陷），

## 四、画板比对工具（`apps/web/scripts/`）

这一节修的是**工具缺陷**，不是概览页本身。但它决定了"截图对比"这件事是否可信，
所以必须记下来：修之前，所有画板的参考图都是错位的。

原裁剪表是**手填**的：每个画板一行 `{left:140, top:300, width:2680, height:1230}`、
期望 `1340×615`。而实测屏幕内区是 `{80,372,2880,1800}` = **1440×900**。
后果不是"对比图略偏"——参考图左边多出侧栏外空白、右边裁掉了内容，
缩放后**两边字号不一致**，人眼看到的差异全是裁剪误差造成的假象。

另有一处更隐蔽的污染：画板上用**品红（`#e01e80`）/ 紫罗兰（`#b969e2`）标注记号**
标编号与引线，这些记号**压在屏幕内容上**。逐像素测量会把记号本身当成内容——
实测「最近笔记」标题行墨迹从 y394 起，而 y394..395 那两行其实是品红角标，
标题真正从 y409 才开始。不清理就会得出"标题位置错了 15px"这种假结论。

| 文件 | 状态 | 作用与原因 |
|------|------|-----------|
| `scripts/lib/supplement-crops.mjs` | 新增 | 把"怎么量出屏幕内区"写成可测代码。判据：窗口边框色恒为 `#d8d8de`（2 设备像素宽）→ 找竖线 → 按**已知视口宽**（2880/780）推右缘并验证 → 行覆盖率找顶边 → **高度查表**。最后一条最关键：画板上的屏常比视口高（实测有 1440×1225、390×1001），量出多高就裁多高会得到与截图对不齐的参考图。同时导出 `isAnnotationMarker()` 清理标注记号 |
| `scripts/lib/__tests__/supplement-crops.test.mjs` | 新增 | 17 条。**每一条都对应实现里真踩过的坑**：内部竖直分隔线（D-05/07/10/13 同一块屏上下展示两态，只配相邻列段会算出 1454 宽而整块丢弃）、状态缩略图混入（取"第一条/最后一条"边框行会把缩略图圈进来）、圆角导致的连通性断裂、长图截断、多台手机排序、记号残影让卡片宽度读成 179（真值 190） |

## 审计要点

1. **`scripts/lib/supplement-crops.mjs` 的「高度查表」是本次最容易被误当成多余的一行。**
   它看起来像常量表，实际是唯一能保证参考图与浏览器截图可比的机制。删掉它、
   改回"量出多高裁多高"，并排图会一边长一边短，而**所有几何断言仍然全绿**——
   因为断言量的是实现，不是参考图。要看的是那份测试里"屏比视口高时只取顶部视口高度"。
2. **概览页不渲染顶栏是个有代价的决定。** 它让"概览"成为唯一没有顶栏的工作区页面，
   `app-shell.tsx` 因此多了一个分支。代价换来的是画板要求的"卡片即页头"，
   以及同一屏不会出现两套同名控件。若要回退，`isKnowledgeBaseOverviewRoute` 是唯一开关。
3. **`pt-7` 不是随手加的魔法数。** 去掉顶栏后内容会贴到窗口上沿（画板从 y=27 起），
   这 28px 补的是顶栏原本承担的留白。改顶栏高度时必须同时看这里。
4. **5 格的两个易错点都写进了测试**：数据未到时给骨架而不是 0（先显示「0 篇笔记」
   等于告诉用户库是空的）；"与侧栏一一对应"用 href 集合比对而不是下标——下标配对
   在导航增删一项时会静默错位，配上 `toHaveCount(1)` 恰好还能过，是最糟的假绿。
5. **`knowledge-base-detail.tsx` 少了 113 行**（−316/+213 的一部分）。它现在只服务
   资料与成员两个 Tab。评审时可以顺手确认没有别处仍在 import 已移出的符号
   （`tsc --noEmit` 已确认，但那是编译期检查，看不到"语义上该用新页却仍在用旧页"）。
6. **侧栏宽度分档只改了一处判断。** 若后续新增非 `/notes/{id}` 形态的知识库路由
   （例如组织知识库走 `/orgs/{id}/...`），`parseBaseIdFromPath` 不认，侧栏会退回 272
   而库卡片需要 296——那时要扩展的是这个函数，不是加第二处判断。
7. **`KnowledgeBaseMissing` 现在仍是死代码。** 它实现的就是"找不到这个知识库"兜底态
   （D-02 图例要求的那一个），但**从未被任何地方引用过**——这本身就是它为什么
   没拦住「库不存在渲染假数据」那条缺陷的原因。本次改用方案 12.0.3 定稿的共用组件
   `NotFoundState`（文案与它一致；该组件已在 8 处服务慕课详情、任务详情、协同工作区
   与本次的概览页），没有复活它。
   评审时值得确认：是否该把它删掉，避免下一个页面又误以为"兜底已经有了"。
8. **骨架形状是"与宿主同高"这一条最容易被简化掉。** `KnowledgeBaseOverviewSkeleton`
   里那些 `h-[98px]` / `h-[260px]` 看起来像硬编码的魔数，其实是画板实测的真实高度。
   改成 `h-24` 之类的近似值，加载完成时页面会纵向跳一下——而**所有断言仍然全绿**
   （单测只检查槽位与类名存在）。要守住的是 E2E 里那条"过渡态灰块落点"的实测。

## 未完成项与偏差（如实记录）

1. **首轮全量 E2E 出现过 1 条偶发失败：`ui-supplement.spec.ts` 的 D-10 协同文档库删除用例。**
   失败点是等不到「删除 {标题}」按钮；单跑 3/3 通过，随后两轮全量均为 **126/126 全绿**，
   未再复现。根因是文档库走协同索引房间，"新建 → 出现在列表"要等 WebSocket 房间同步，
   属**既有**的时序问题（该用例注释里已记录过同类现象）。
   **与本次改动无关**：本次没有触碰 `/docs`、协同服务或索引房间的任何代码。
   没有修它是因为超出本次授权范围（用户要求的是概览页还原）。

2. **只读成员分支没有真实栈 E2E。** 图例 9 要求「新建笔记」在可阅读及以下权限隐藏，
   但要造一个只读成员需要另一套账号 + 成员关系。E2E 只断言了可编辑时的正向行为，
   权限分支由单测覆盖（`permissions` 1/2/3/4/undefined 五种）。
   这是**覆盖率上的缺口**，不是未实现。

3. **「最近笔记」的条数上限是 5，但列表查询用的是默认页大小。** 当默认页大小小于 5
   时预览会少几条。当前 `DEFAULT_PAGE_SIZE` 大于 5，所以没有实际影响；
   若将来下调它，这里会静默变少——没有为此加断言，因为那时更该做的是
   让预览单独请求 `pageSize=5`。

4. **画板上的品红/紫罗兰记号是按色相识别的，不是按图层。** 也就是说，
   如果设计里真的出现同色系的正常内容（例如紫罗兰 `/ai` 品牌色），它会被一并抹成白色。
   本次核对了 D-xx / M-xx 全部 40 张画板，未发现同色内容；这个风险记为已知限制，
   写在 `isAnnotationMarker` 的注释里。

5. **`/m/*` 移动端概览页不在本次范围。** D-02 是桌面画板；移动端知识库内是
   另外三块（M-03 慕课 / M-04 任务 / M-05 资料），没有概览页。
