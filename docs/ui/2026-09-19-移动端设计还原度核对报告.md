# 移动端设计还原度核对报告

> 日期：2026-09-19（Asia/Hong_Kong）  
> 环境：[线上测试环境](https://note.zch.one/)  
> 依据：[UI补稿设计图.md](UI补稿设计图.md)，2026-09-16 定稿版  
> 结论：**主要移动端路由与交互骨架已落地，视觉还原度中等，尚未达到按稿验收标准。**

## 1. 核对范围与结论

本次直接打开线上 `/m/*` 页面，在 **390×844 CSS 像素**视口逐页检查，实际切换浅色、深色，并操作搜索、筛选、新建面板、历史预览等。不是把 PC 页缩窄后当作移动版，也没有用本地代码或旧报告代替线上结果。

13 块移动画板中，**12 块已访问对应真实页面，M-12 任务详情因当前账号可见知识库没有任务而未进入**。M-04 仅覆盖空列表与筛选，M-06 仅覆盖空课程目录和未选内容态，不能据此宣称正常数据态通过。其余页面也未穷尽所有异常、权限和加载分支。

主要结论：

- **路由与结构较完整**：知识库内慕课/任务/资料 Tab、协同文档、搜索、新建笔记、设置、两级历史版本都可到达。搜索与编辑/历史页隐藏底部导航，知识库子页保留导航选中态。
- **视觉系统存在跨页面偏差**：分组背景使用成了统一纸面背景；深色卡片与整页同色，层次变弱；底栏胶囊、主按钮、返回按钮尺寸与稿件不同。
- **显著单页问题**：工作台标题偏小、内容段留白过大；“我的”缺少彩色设置图标；搜索缺少匹配高亮；历史预览返回键放右侧、正文标题重复、恢复按钮不贴底。
- **交互已实现但细节未齐**：标题校验、搜索无结果预填、性别动作表、历史恢复面板、协同更多格式面板均能打开；多个动作表没有可见“取消”项。

不提供“像素还原率 xx%”：没有相同业务数据、真机系统栏和统一像素配准，给出百分比会造成虚假精度。下文按“较接近 / 部分还原 / 明显偏离 / 覆盖受限”分项评价。

### 环境与边界

- 浏览器为 Codex 内置浏览器，桌面浏览器引擎 + 手机尺寸视口；**未模拟移动 UA、触控和软键盘，不等同于 iOS/Android 真机验收**。
- 用户登录后停在 `/notes`，随后主动进入 `/m/dashboard`。本次没有验证手机 UA 的自动分流；桌面浏览器登录落 PC 页本身不列为缺陷。
- 当前知识库列表“全部”仅显示 `Test`（56）：3 篇笔记、1 门课程、0 个任务、1 份 PDF；课程 `test`（10）没有章节。协同文档库存在可访问文档，使用既有 `Test` 文档检查。
- 只输入搜索词与未保存的校验标题；没有新建业务数据，没有执行删除、恢复、任务提交/退回、改密码或保存资料。打开协同编辑页期间列表更新时间发生变化；未输入正文或标题，不能保证页面自身没有产生连接/索引副作用。
- 检查结束已将主题还原为原来的“跟随系统”。
- AI 正文、设置 AI 内容区按设计决定不评视觉；原稿 p07–p09 只作为进入补稿页面的路径检查，不混入本次 13 块画板评价。

## 3. 差异清单与修复优先级

优先级是本次视觉审查分级：高 = 显著影响主要信息层级、阅读或操作可达性；中 = 元素、尺寸、样式或明确交互要求不符；低 = 文案、顺序及辅助信息细节。不是线上故障严重等级。

| 编号 | 级别 | 设计要求与实际差异 | 建议及复验方法 |
|---|---|---|---|
| V01 | 高 | M-01/02/07/08/10/11/13 等应有分组背景与独立卡片。实际 mobile-shell 使用纸面色：深色外壳 `rgb(28,28,30)` 与卡片同色；浅色整体白底，分组层次丢失。body 虽黑色，已被外壳覆盖，不能只检查 body | 按页面语义恢复 grouped/surface；同时截浅/深，验证分组页卡片与背景可分辨；编辑纸面保留自身语义 |
