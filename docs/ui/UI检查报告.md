## 1. 检查方法

### 1.1 环境

- Docker 全栈 21 个容器全部 `healthy`（web 3000 / gateway 8080 / collab 1234 / MinIO / Nacos / MySQL / Redis / ES 等）。
- 前端是**生产构建**镜像（`infra/Dockerfile.web`），不是 dev server，因此断言的样式与线上一致。
- 浏览器：Playwright 管理的 Chrome for Testing 153.0.8010.12（真实 Chromium，非 jsdom）。
- 视口严格对齐画板：桌面 `1440×900`、移动 `390×844`，`deviceScaleFactor: 2`（与画板的 2 倍导出图同倍率）。
- 登录态：每轮通过真实 BFF 注册临时账号（`/api/auth/register` → `/api/auth/login`），拿 httpOnly Cookie。

### 1.2 比对方法（为什么不是"看着差不多"）

画板是**整幅设计画布**：左上角是屏幕真身，右边几十条图例、下方状态缩略图。直接并排会两边宽度差三倍，人眼对不出任何东西。本次采用四重证据：

1. **自动量出屏幕内区**：画板把屏幕画在 2 设备像素宽、颜色恒为 `#d8d8de` 的窗口边框里，据此纯靠颜色算出裁剪框（复用仓库既有 `apps/web/scripts/lib/supplement-crops.mjs`）。31 块屏幕画板**全部**量出，框位一致为 `1440×900` / `390×844`。
2. **同几何裁剪后并排**：参考图裁到 CSS 像素、截图缩到同尺寸，左右两半同一 `(x,y)` 指屏幕同一位置，垂直方向可直接对。
3. **局部放大**：对需要看细节的横带用 `ui-audit-zoom.mjs` 放大 2–3 倍（设计在上、实现在下）。
4. **DOM / 像素实测**：读计算样式、`boundingBox()`、`data-testid`，以及像素探针（"近白占比"、"墨迹行高"），用数字而不是印象下结论。

### 1.4 本次检查顺带修掉的一个工具缺陷（重要）

仓库原有的 `apps/web/scripts/ui-supplement-compare.mjs` **定义了 `setTheme()` 却从未调用**。后果是所有 `-dark` 截图其实是浅色：

```
d01-kb-notes  light=eb052fda  dark=eb052fda   ← 字节级相同
（30 个场景中 24 个浅深截图 hash 完全一致）
```

这会让"深色还原度"这一项**永远假绿**——报告里写"深色已核对"，而实际上根本没截到深色。本次新增的 `ui-audit-capture.mjs` 修掉了它（按 `next-themes` 的 `theme` key 写 `localStorage` 再导航；登录页无顶栏菜单，改用 `prefers-color-scheme` 驱动），并逐场景断言 `html.dark` 是否真的挂上：

```
✓ d01-kb-notes    light(light) dark(dark)      ← 30/30 场景深色确认生效
```

**建议**：把 `ui-supplement-compare.mjs` 的主题切换一并修掉，否则它每次跑都在产出误导性的"深色对比图"。

## 2. 高优先级问题

### H-1　知识库内 6 个 Tab 多出画板没有的 56 高顶栏　`版式偏差 / 高`

- **画板**：D-01 / D-05 / D-07 / D-08 / D-09 的屏幕区里**没有**横贯内容区的 56 高顶栏；页头（大标题 + 副标题）直接贴着窗口上沿开始，搜索与主题在页头右侧。
- **实现**：`app-header` 恒在，`y=0, h=56`，内容区从 `y=56` 才开始。

| | 画板 | 实现 |
|---|---|---|
| 顶栏 | 无 | `[data-testid=app-header]` `x=296 y=0 w=1144 h=56` |
| `h1` 位置 | 贴顶（约 y=27） | `x=420 y=56`（被顶栏推下 56） |
| 搜索 / 主题 | 在页头动作行 | 在顶栏（`x=1300 y=12`） |

- **证据**：`zoom-d01-kb-notes-light-0-120.png`（放大 3 倍）——画板从「笔记」标题直接开始，实现先有一条 `审计库 xiaqt　普通知识库 ⌄　搜索　🖥` 的横栏。
- **根因**：`app-shell.tsx:33` 的 `hideHeader` 只对**概览页**生效（`isKnowledgeBaseOverviewRoute`），其余知识库内页面照常渲染顶栏。概览页的正确处理（`hideHeader` + 补 `pt-7`）已有现成范式与单测（`app-shell.test.tsx:262`）。

> **需拍板**：这条与 `ui-redesign.spec.ts:165`「顶栏在知识库内只给切换器」的既有断言冲突。那条对的是 PDF 原设计稿（p01–p16）；补稿画板（D-01 等）把动作行搬进了页头。**两稿在这一屏口径不同**，需产品确认以哪稿为准再动代码。

### H-2　M-01 工作台缺搜索框，快捷操作由「一行三格」变「2×2 四格」　`缺失元素 + 版式偏差 / 高`

- **画板**：问候语下方是**一个全宽搜索伪输入框**「搜索知识库、笔记、慕课」（约 `y=122–152`，358 宽、圆角 10、底 `#E9E9EE`）；再往下是**一行 3 张**图标在上/文字在下的快捷卡片。
- **实现**：**没有搜索框**；快捷操作是 **2×2 四格**，图标在左、文字在右，多出第 4 格「搜索」。

```
画板： [搜索知识库、笔记、慕课          ]   ← 全宽伪输入框
       [新建笔记] [AI 对话] [协同文档]      ← 一行三格，图标在上
实现： [新建笔记] [AI 对话]                ← 2×2，图标在左，无搜索框
       [搜索]     [协同文档]
```

- **实测**：`grid-template-columns: 173px 173px`（两列），`nav` 内 4 项，`y=72/140` 两行；`input[placeholder*="搜索"]` 数量 **0**。
- **依据**：方案 §12.7.7 明写「入口：工作台顶部搜索框」；`UI补稿设计图.md` M-01 图例 3 是「搜索（伪输入框）358×36 圆角 10 → /m/search」。但**附录 A 的 M-01 表只列了图例 11/12/18 三条**，搜索框不在"橙字改动"清单里——这正是它被漏掉的原因。
- **代码位置**：`mobile-dashboard.tsx:30-35`（`QUICK_ACTIONS` 4 项）、`:93-104`（`grid grid-cols-2`）。

### H-3　M-11 设置缺头像/用户名块，密码规则横向排布变纵向四行　`缺失元素 + 版式偏差 / 高`

### H-6　M-10 搜索结果图标渲染成圆形，画板要求圆角方形　`图片/图标偏差 / 高`

- **画板**：知识库行的色块是 **30px 圆角 8 的方形**；「创建笔记」行是**蓝色方形图标块 + 笔形图标**。
- **实现**：色块渲染为**正圆**；「创建笔记」用 `Sparkles`（星芒）而非笔形。

- **证据**：`zoom-m10-search-light-180-330.png`（上=画板方形，下=实现圆形）。
